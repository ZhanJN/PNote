# 同步协议 `pnote-sync/8`

> 纯局域网、点对点、无服务器、无认证、明文传输。只在可信任的家庭网络里使用。

## 一、发现

- 端口：**UDP 47821**（接收绑 `anyIPv4:47821`，所有网卡一起收）
- 广播：每个本地 IPv4 一个发送 socket，同时发 `255.255.255.255:47821` 与定向广播 `a.b.c.255:47821`；载荷是 UTF-8 JSON（设备号、设备名、同步端口、协议版本、账号名、时间戳）
- 兜底：广播收不到时按网段并发扫描（并发 64，单点超时 350 ms，总预算约 8 s）
- 过滤：跳过虚拟网卡（VMware/VirtualBox 等）；同网段优先，同优先级取「最近见到」的

## 二、传输

- **WebSocket**，端口从 47822 起，占用则 47823…47831（`47822–47831 端口都被占用`时直接报错）
- 超时：连接 5 s、发送 10 s、接收 15 s、整场会话 90 s 兜底
- 每个连接两方对称：谁拨号谁发起，服务端负责合并与回包
- 多设备：一轮之内按顺序与所有对端各交换一次，最多 3 轮（轮间 300 ms），把 A↔B 的改动经 C 传给 D

## 三、帧

所有帧都是 UTF-8 JSON 对象，顶层必有 `proto`（必须等于 `pnote-sync/8`，否则拒绝并提示协议版本不匹配）与 `type`。

### 1. `state`（第一帧，双向）

```json
{
  "proto": "pnote-sync/8",
  "type": "state",
  "deviceId": "…", "deviceName": "…", "account": "我的 PNote",
  "hlc": {"ms": 1732500000000, "c": 3, "dev": "…"},
  "sentAt": 1732500000000,
  "tasks": [ { "id": "…", "createdAt": 0, "kind": 0,
               "fields": { "title": {"value": "…", "hlc": {"ms":0,"c":0,"dev":"…"}}, "…": {} } } ],
  "purged": [ { "id": "…", "hlc": {"ms":0,"c":0,"dev":"…"} } ],
  "notes":      [ { "path": "2026/11/x.md", "hlc": {...}, "sha": "…", "size": 123 } ],
  "noteDels":   [ { "path": "2026/11/x.md", "hlc": {...} } ],
  "notePurges": [ { "name": "2026-11-24 0200 x.md", "hlc": {...} } ],
  "want": ["2026/11/y.md"]
}
```

- `tasks` / `purged`：任务侧全量状态（含墓碑，`deleted_at` 是普通字段）
- `notes` / `noteDels` / `notePurges`：笔记侧元信息；旧客户端不认识这些键会忽略
- `want`：本机缺少或版本落后的笔记路径，请求对方发内容


> **1.51 起（`/8`）多一条硬规则：`account` 不同就不合并。**
>
> - 监听方收到 `state` 后先比 `account`，不同则一条任务/笔记都不落库，回 `ack(ok:false, message:"账号不同", account:<本机账号>)` 并关闭连接；
> - 拨号方连上后也会校验回包里的 `account`，防止「同名但其实是另一拨人」的设备；
> - 失败在界面上显示为「账号不同（对方「X」）」，不是「协议不兼容」——前者是操作问题，改个名字即可；
> - 发现广播（UDP）里也带 `account`，连接设备页会把不同账号的设备灰显标注；扫描兜底找到的候选没有账号信息，连上后才判定。

### 2. `blobs`（内容帧，可多帧）

```json
{ "proto": "pnote-sync/8", "type": "blobs",
  "blobs": [ { "path": "2026/11/y.md", "hlc": {...}, "bytes": 1234, "data": "<base64>" } ] }
```

单帧按 base64 膨胀后的长度控制在 1 MB 左右。

### 3. `blobsDone`

```json
{ "proto": "pnote-sync/8", "type": "blobsDone", "want": ["…"], "skipped": 2 }
```

`want` 是「我还需要这些」，`skipped` 是因为超过 32 MB 上限（`kMaxSyncFileBytes`）而没发的数量。

### 4. `ack`

```json
{ "proto": "pnote-sync/8", "type": "ack", "ok": true, "message": null }
```

`ok == false` 时客户端会把 `message` 抛给 UI，不再静默吞掉。

## 四、一次交换的顺序

```
A → state(A 的全量 + A 的笔记元信息)
B → state(B 的全量 + B 的笔记元信息 + B 的 want)
A → blobs(B 要的) → blobsDone(want: A 还缺的)
B → blobs(A 要的) → blobsDone()
A → ack
```

- 服务端处理帧必须**串行**（`Future` 链），否则笔记内容还在写 `.tmp` 时 `blobsDone` 就到了，另一侧会以为文件不存在。
- 收到 `state` 后先落「笔记删除/彻底删除」这类元信息，再回包，避免把刚被删的文件又发出去。

## 五、混合逻辑时钟（HLC）

- 本地事件：`pt > l` 时 `l = pt, c = 0`，否则 `c += 1`
- 收到远端：`l_new = max(l, l_m, pt)`，按分支决定 `c`
- 比较：`(ms, c, deviceId)` 字典序。`deviceId` 是设备首次启动生成的 UUID，存在 `meta` 表里，永不改变
- 不用 NTP：快钟最多能让本机「赢 5 分钟」，可接受

## 六、合并

- 任务：逐字段 LWW；`purged` 求并集取较大 HLC；`kind` 本机优先
- 笔记：内容按 `blob.hlc` 与本地 `.sync.json` 里的版本比较，新的原子写入（先 `.tmp` 再 rename），旧的丢弃
- 彻底删除：只要对端记录更新，就按**文件名**删掉本机的正文、素材目录、以及回收站里的副本；被彻底删除过的路径不会再被 `want` 拉回来
- 幂等：合并结果再合并一次必须不变（有单测）

## 七、已知取舍

- 明文、无认证：谁在同一网段都能连上来；不做 TLS 是刻意的（零配置优先）
- 全量交换：任务量在几千条以内时简单可靠，更大规模需要增量
- 附件上限 32 MB；音视频不进同步
- 协议主版本不符直接拒绝，两端必须同版本
